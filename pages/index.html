The docs folder is where context goes to die.

Every team keeps the reasoning behind its code somewhere: a Markdown folder in the repo, a Notion space, a few notebooks. The folder goes stale because nobody reads it. The wiki is far from the code and farther from the agents. Nobody is sure who keeps what up to date.

Uberblick is one workspace for the three who need that reasoning: the agent that writes the code, the engineer who runs the agent, and the product manager who asked for the feature. Each has its own way in, MCP for the agent and the browser for the people. Evidence, numbers and decisions land in the workspace instead of in one engineer's chat session.

Agents over MCP

An agent gets the pages its change needs without cluttering its context window. The server sorts the relevant from the irrelevant: it names the few pages tagged as guidance when the agent connects, the decisions linked to the issue come with one call, and search finds the rest. Implementation agents get pointers to the right pages and read them over the local MCP server. No prompt engineering, no context spamming, no hoping.

Works best with ub-agents.

agents.uberblick.ai

Uberblick holds what the product should do; it does not track tasks. Delivery lives on GitHub, and ub-agents is the loop that runs it there: roles in a few lines of YAML, driven by labels, on Actions, with any agent and no server. Every issue starts from the pages and every pull request brings them up to date. Retrospectives propose changes to the pages and to the loop's own rules; a person decides each one. It is how Uberblick itself is built, and we write down how that goes.

What a document can hold.

Custom Markdown

Markdown, plus the few additions that let an idea be drawn instead of described. Each one is text with a source form, so an agent can write it and a person can read it, and each ships as its own package.

  • ablaufFlow diagrams as text. The author places the nodes; the renderer only draws.
  • wireframeA screen sketch in a few lines, drawn by the editor.
  • chartCharts and tables drawn from records stored in the page. New records, new chart.
  • cardThe one recommendation, with a button that opens the discussion in Claude Code or Codex.
  • figmaA Figma file, frame or board on the page. Figma is contacted only when a reader opens it.
  • and the restLinks by id, GitHub pills, inline icons, terminal transcripts. Everything stays Markdown an agent can write.

Decisions

As the editor shows it. The question is the title. The record on top is under review: a proposed answer, the report it rests on, and the RFC page where the discussion happens. The history below keeps every record on the topic, the answer in force and the ones it replaced, so nobody has to ask why twice.

Start in three commands.

Install and update

Homebrew on Apple Silicon macOS or Linux x86_64, run in your repository's directory. No account, no server. The last command registers the MCP server with Claude Code; use codex for Codex. To share a workspace, run a hub on a computer the team can reach: one Docker release, see Run a hub.

Terminal
$ brew install uberblick-ai/tap/uberblick
$ ub workspace create "My Workspace"
$ ub open
