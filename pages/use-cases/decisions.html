Decisions that stay decided.

Agents are good at reopening questions. Each run starts fresh, finds the same trade-off and proposes the same fix a person already said no to. A decision record ends that: the answer is on a page, linked from the issue, and every agent that touches the issue reads it first.

The question

In October our agents were drawing flow diagrams in design pages with Mermaid, and the pictures were bad in a way nobody could fix: automatic layout moved every node when one was added, and an agent that was told "the arrows cross" had nothing to grab. Removing Mermaid would mean a few dozen pages lost their diagrams. Keeping it meant more pages like them.

The record

Decision · decided 15 October 2026Uberblick product workspace

Support for Mermaid

Not supported. Mermaid fences are ordinary code blocks and are never drawn. Flow diagrams use ablauf, where the author places the nodes and the renderer only draws and reports crossings.

Automatic layout has no handle an agent or a person can hold: every change reflows the picture, so review cannot tell a change in meaning from a change in position. A text format with explicit placement keeps the diff readable and lets an agent repair a diagram from diagnostics alone. The cost is a renderer of our own, which is small, and re-drawing existing diagrams, which the loop can do.

The record was proposed by the agent that prepared the issue, with the trade-off written out and the stage left open. Ben approved it in the browser; the answer went in force under his name and date. The earlier record on the same topic, from the week Mermaid was added, is one row below it in the history.

What happened next

  1. The removal shipped in 0.4.5. The implementer called find_decisions for the issue, read the record, and removed the renderer without proposing a toggle to keep it. Its pull request's corpus update changed one block on the Custom Markdown page.
  2. The replacement shipped in 0.4.8. Ablauf went from a format in its own repository to a block drawn in the editor. The preparer of that issue found the same record and cited it as the reason the block exists.
  3. The question came back. A later issue asked for "Mermaid import". The preparer found the record, quoted the answer in the issue, and proposed a narrower job instead: convert the old Mermaid fences to ablauf once. That is what got built.

Changing a decision

When the answer should change, Alter decision on the topic page opens a new record with the current answer prefilled. The person edits, approves, and the topic shows the new answer with the old one in its history. Nothing is overwritten and nothing has to be remembered. How decision records work.
