Uberblick / Use cases

Reports with the numbers inside.

A report that pastes a chart is stale the next morning and nobody can tell. In Uberblick the numbers are records stored in the page, the chart is a mapping onto them, and the agent that gathers the numbers writes records instead of prose. The report stays true because the data does.

Two pages we keep pinned

The Delivery report says what the loop shipped this week: pull requests opened and merged per day, how many needed a person, how many runs were wasted and why. The CI health report says how often the merge gate was red and which check caused it. Both are pinned at the top of the sidebar, both are read by people on Monday, and neither is written by a person.

How a page gets its numbers

  1. A skill gathers. A GitHub Action runs a small skill that asks GitHub for the week's pull requests and check runs and turns them into records: one per day, with the fields the charts need.
  2. It writes records, not sentences. ub data update "Delivery report" --file week.json applies one validated batch to the page's pull_requests collection. Records that fail the schema are kept and marked; the chart leaves them out and says how many.
  3. The charts refresh. The line chart and the data table on the page map onto the collection, so they show the new week with no edit to the page.
  4. An agent writes the paragraph and the card. With the numbers in place, an agent writes two sentences of what changed and a card with the one recommendation, linking the issue it rests on. A person reads, comments on the sentence that is wrong, and the agent fixes that block.

What it looks like

```chart
{
  "version": 1,
  "type": "line",
  "title": "Pull requests per day",
  "collection": "pull_requests",
  "x": {"field": "day", "type": "date"},
  "y": [
    {"field": "opened", "label": "Opened"},
    {"field": "merged", "label": "Merged"}
  ]
}
```

The card at the end of the report is the only part a reader has to act on. Its button opens the discussion in Claude Code with the question already asked.

:::card
label: Recommendation
title: Cut the retry limit to two
footer: From the delivery report of 16 October
button: [Discuss in Claude Code](claude://code/new?prompt=Review%20the%20retry%20limit) filled blue
button: [Open the issue](https://github.com/uberblick-ai/uberblick-2/issues/1588)

Three of this week's wasted runs were third retries on the same failure. A limit of two would have stopped each one a run earlier.
:::

Why not a dashboard

A dashboard shows numbers without the reasoning; a report explains numbers it cannot show. This page is both, and the agent that explains has the same records in front of it that the chart draws. When a number looks wrong, the person comments on the chart's caption and the agent checks the records, not a screenshot. Charts and data tables has the shapes.
