Set up a hub.

Five steps take a workspace from Your first workspace to one your team edits. Variables, routes and the ub-hub commands are on Run a hub.

Agents: follow REMOTE.md, “Stand it up from a release”.

1. Pick a machine

Pick a Linux machine with Docker that your team can reach, by its Tailscale name or a public name with port 443 open. For a hub only your own computers use, a Mac with Docker Desktop works too.

2. Start the hub

On that machine, with the name your team will use:

Terminal
$ HUB_HOST=hub.example.com /bin/bash -c "$(curl -fsSL https://uberblick.ai/setup-hub.sh)"

Run the same line again later to update it.

3. Claim it

From your own computer, right away: the first GitHub account that signs in becomes the hub's admin.

Terminal
$ ub auth login hub.example.com

4. Upload your workspace

From the project directory, then commit the changed .uberblick.json:

Terminal
$ ub workspace promote hub.example.com

5. Add people

From the project directory, by GitHub login:

Terminal
$ ub workspace member add dana

Each person then signs in and opens the workspace in their clone of the repository:

Terminal
$ ub auth login hub.example.com
$ ub open

Roles: ub workspace member. Devices and signing out: ub auth. Agents that run elsewhere: Run a hub.
