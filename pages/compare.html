Is Uberblick a good fit?

Uberblick is a narrow tool: the plans, decisions and numbers behind one codebase, kept where the coding agents, the engineers and the product people all read them. It is version 0.4, built by a small team, and you host it. For a lot of knowledge work one of the tools below is the better choice, and this page says when.

A good fit when

  • Coding agents work in your codebase. You want them to read the plan and the decisions before they build, and you would rather enforce that than hope for it. Agents reach the workspace over MCP; Claude Code and Codex are set up with one command.
  • The documents are about one product. Product intent, design notes, decisions, reports with numbers, the flows and screens behind them. A few people to a few dozen, engineers and the product people who work with them.
  • You want it on your own machines. Every computer holds the full workspace and works offline. Sharing means running one Docker container somewhere the team can reach, or nothing at all for a workspace of one.
  • You are at home in a terminal. Install with Homebrew, bind a project with a small JSON file, write Markdown with a few extra block types. There is no onboarding flow and no account to create.
  • You already have an agent you trust. Uberblick has no AI of its own: no model, no key to paste, no assistant in the corner. The agent you already use, with your keys, is the one that reads and writes here. The product is the shared memory, not another chatbot.
  • Delivery lives on GitHub. Issues and pull requests stay there; Uberblick links to them and never tries to be a tracker. If you run an agent loop on GitHub labels, the pages feed it.

Not a good fit when

  • The content is company-wide. Onboarding, HR, sales, meeting notes for everyone: Notion, Confluence or Google Docs do this better and will keep doing it better. Uberblick has no templates, no databases with views, no public pages.
  • You need someone to host it. Nobody hosts Uberblick for you today. Local-only works without a server; sharing needs the hub you run. If "run a container" is a blocker, stop here.
  • Your team is on Windows, or wants a phone app. The client installs on Apple Silicon macOS and Linux x86_64. A phone can read and comment on a shared workspace in the browser; there is no app and no Windows build.
  • You need enterprise permissions. A workspace has members and admins, signed in with GitHub. No SSO, no per-page rights, no audit log. Reading and writing are the same right on purpose.
  • Your issues live in Jira, Linear or GitLab. Uberblick links to GitHub and only GitHub. Other trackers may come; they are not here.
  • You want a task board. There is none and there will not be one. Delivery tracking belongs to the tracker.
  • You want a personal notes app. Obsidian, Logseq and Trilium are better at one person's notes, faster, with thousands of plugins. Uberblick is a team workspace with a sync protocol, which is overhead for one person's thinking.
  • You want "ask the wiki" out of the box. Without an agent connected there is no AI in Uberblick at all: no question box, no summaries, no generated pages. Notion, Confluence and Outline ship that and a team that wants it with zero setup should take it.
  • Your agents do not speak MCP. There is a CLI for data and a small HTTP API behind ub open, but the agent interface is MCP. An agent that can only call a REST API is on its own.
  • You cannot live with a 0.4. Things change between releases. Last month a sync protocol change made everyone sign in again. If that is unacceptable, come back later; the changelog says what moved.
