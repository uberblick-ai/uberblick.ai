Is Uberblick a good fit?

Uberblick is a narrow tool. It holds the product intent, the decisions and the numbers behind one or more codebases, close to where the coding agents and the engineers work. Product managers define and adjust that intent in it and enrich it with data from other systems, Mixpanel or New Relic for instance. To be fair: it is early, and it is built by a small team with no ambition for profit. We had our success in the startup ecosystem; this is our approach to give back. We are amazed how fast we can build the system itself with the raw power of Uberblick and ub-agents, but you should enjoy being a bit of a beta tester.

If you start with a fresh idea, or feel the pain of too many outdated Markdown files, and you like that you can still influence where the product goes, feel free to use it. Below is when it fits, when it does not, and how it compares.

A good fit when

  • A technical and product-minded team of hands-on people, usually shipping with coding agents, whose product has clear principles and boundaries.
  • The Markdown folder in the repo went stale, and plans made with an agent on one machine never left it.
  • New agent sessions get too much context from local Markdown files, or miss the guidelines they should have read first.
  • Decisions keep coming back because the last answer is a paragraph somewhere, and you would rather have a record that agents look up before they build.
  • The team is confident extracting relevant numbers into reports, so the chart on the page is the data and not a screenshot of a dashboard.
  • Local and offline matter, and MCP is the main way in: the agent you already use, not another assistant.
  • Delivery lives on GitHub, and the reasoning should live next to it in a place that was built for agents, not retrofitted.

Not a good fit when

  • The content is company-wide: onboarding, HR, sales, meeting notes for everyone. Notion, Confluence, Outline or Google Docs do this better. Uberblick focuses on small product and tech focused teams.
  • You need someone to host it. Nobody hosts Uberblick for you; sharing needs the hub you run. But it is just a Docker Compose file, plus the backups and upgrades any service needs: Run a hub.
  • You want tasks. There are none and there will be none. Uberblick is not a task manager; delivery lives in the tracker.
  • Your issues live in Jira, Linear or GitLab. Uberblick understands GitHub references and only those today; anything else is a plain link.
  • Your team is on Windows. We are on macOS and Linux so far; Windows might work, and if you need it, we can make it happen. Phone support will come; today the editor is for desktop browsers and iPad.
  • You need fine-grained permissions. A workspace has members and admins, signed in with GitHub. No SSO, no per-page rights, no read-only role, no audit log.
  • You want "ask the wiki" built in. Uberblick has no AI of its own, and that is deliberate: quite frankly, MCP in your favourite AI desktop app has come a long way, and the built-in approaches we have tried feel outdated next to it. If an assistant inside the product is what you want, Notion, Confluence, Outline, AFFiNE and Falconer ship one.
  • You use it as a solo developer. It might work: Uberblick was started by a solo developer and it helped. But Obsidian or Trilium are probably better suited to one person's notes.

Some of the above, tasks aside, may be added later. We are focused on getting the core of the app right and will expand on what is requested and what feels right. File an issue and request what you need.

Side by side

"Agents" means how a coding agent reads and writes the documents. Hosted tools first, then open source and source-available tools. Markdown in the repo is in the second table because it is the honest baseline. A cell such as "A doc" under Decisions means the tool has no decision type: you write the record as a document and keep your own convention. Where a feature needs a paid plan or an extension, the cell says so.

Where the others are stronger: Notion, Confluence and Outline for company-wide knowledge with mature sharing and administration. Google Docs for reviewing prose with people outside the team. Obsidian and Markdown in the repo for plain files you own outright, with history and diffs for free. Jupyter when the numbers behind a decision must be computed, not just stored. And every tool with an official MCP server gives your coding agent a way in too; that is no longer an Uberblick-only trait.

What you take on with Uberblick: you run the hub and its backups and upgrades, clients and hub move to a new protocol together, and a member you remove keeps the documents already on their disk. export_markdown gives any page back as a Markdown file with the blocks as fenced source, so leaving is possible, but it is not a folder of Markdown while you use it.
