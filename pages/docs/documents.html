Uberblick / Docs / Core concepts

Documents

A workspace is a set of documents and nothing else: no folders, no databases beside the pages, no tasks. A document is a page of blocks. People and agents see the same page, the same block ids and the same revisions, so a sentence an agent wrote and a comment a person left on it refer to one thing.

A page of blocks

A document has a title, an optional one-line description and an optional TL;DR, then blocks: paragraphs, headings, lists, quotes, tables, code, and the blocks Uberblick adds. Every block has a stable id and a revision. An agent edits one block against the revision it read, and a stale read comes back with the current text instead of overwriting it. A comment anchors to a block, so it survives edits around it. Replacing a whole page would throw both away, which is why no tool does that.

Links by id

A link to another document is a reference by id: [label](document-uuid). It survives renames and counts as a backlink, so a page knows which pages point at it. A link to a GitHub issue or pull request is recognised as such and shown with its number. Decision records link the issues they govern the same way, which is how find_decisions answers "what was decided about #1588".

Comment threads

A thread is attached to a range of text inside one block. People open threads in the browser; agents open and answer them with annotate, and see which threads are open on a page before they edit it. A block with an open thread cannot be deleted. Resolving a thread keeps it in the page's history. Most of the review between a person and an agent happens here, as short questions on the exact sentence rather than a chat about the page.

The sidebar is curated

The sidebar is not a file tree. It holds named groups of pinned documents in the order someone put them, and the documents that matter most sit at the top. An agent starts from the same list, through get_sidebar. Everything that is not pinned is still live and reachable through search and the full list; it is only not on the shelf.

Tags, kinds and lifecycle

Tags are a catalogue with stable ids, so renaming a tag renames it everywhere. One tag, guidance by default, marks the pages agents are pointed at first. A document has a kind: a regular page, or a decision record with its own fields and rules. A document is live, or archived; an archived document still answers reads by id, can be restored, and on a hub can be deleted for good. Search covers titles, descriptions, content and tag names, and is the same index for people and agents.

Data in the page

A document can own collections of records with a schema. A chart or a data table in the page draws from them, so the numbers are in the page and not in a screenshot. Agents update records with update_data, scripts with ub data update, and the chart follows. See Charts.

In and out

export_markdown gives any document back as one Markdown file, with the Uberblick blocks as fenced source that other tools at least show. The workspace itself is one SQLite file per computer, described on Your first workspace.
