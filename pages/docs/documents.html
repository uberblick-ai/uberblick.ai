Uberblick / Docs / Core concepts

Documents

A document is where the team writes down what the product should do and why: the brief behind a feature, the decision that settled an argument, the report that shows how last week went. A workspace is documents and nothing else: no folders, no tasks, no database beside the pages. People and agents read and write the same pages, so a paragraph an agent wrote and the comment a person left on it are about one thing.

What belongs in one

Product intent, in the team's own words. What a feature is for and what it must not do. Which option was chosen and what evidence tipped it. How a flow goes, drawn as a diagram or a wireframe instead of described. What the numbers said this week. Each of these is a page that stays true as the product changes, because the people and the agents who change the product update it.

What does not belong: tasks and their status, which live on GitHub, and technical documentation, which lives in the repository next to the code. An agent that implements an issue reads the pages the issue points at, builds, and brings the pages up to date in the same pull request. The pages are the context; the issue is the pointer.

Write for a reader who arrives cold

Give a page a title that says what it is about, a one-line description, and a TL;DR when the page is long. An agent reads the title and the description first to decide whether the page matters for its change, and so does a teammate skimming the sidebar. Keep one topic per page and keep pages short; a page that answers one question is easy to point at from an issue and easy to keep true. Write in Markdown, with the few additions that let an idea be drawn.

Talk about the sentence, not the page

A comment sits on a range of text, not on the page. Select the sentence you doubt and ask; the agent that wrote it sees the open thread before it edits again and answers in place, and you resolve the thread when the text is right. Most of the review between a person and an agent happens this way, as short questions on exact sentences rather than a chat about the whole page. Resolved threads stay in the page's history, so the reasoning behind a paragraph is one click away.

Link pages to each other and to GitHub

A link to another page survives renames and shows up as a backlink on the page it points at, so a decision record knows which briefs rely on it. A link to a GitHub issue or pull request is recognised and shown with its number. This is how an agent asked to work on #1588 finds the decisions that govern it: decision records link the issues they settle, and one call returns them.

Keep the numbers in the page

A page can own data: any JSON, kept in named collections, and a chart or a table in the page draws from it. A weekly report then has its numbers in the page, not in a screenshot, and a reader can comment on the record that looks wrong.

We use it to keep the relevant subset of what lives elsewhere. An agent fetches from another source over MCP, works out what matters and stores that in the page for reference. Our own example: once a week an agent reads the CI runs from GitHub, takes the median run length and stores it as one record with the date. A line chart on the page shows how long CI takes over time, and the discussion about it happens in the comments next to it. Scripts write the same way with ub data update.

When a page has served

Archive it. An archived page still answers when something links to it, can be restored, and on a hub can be deleted for good. Any page can be exported as one Markdown file, with Uberblick's own blocks as fenced source that other tools at least show. The workspace itself is one SQLite file per computer; Your first workspace shows where it lives.

How this works underneath

A page is a list of blocks, each with a stable id and a revision. An agent edits one block against the revision it read, and a stale read comes back with the current text instead of overwriting it; comments anchor to a block and survive edits around it. That is why no tool replaces a whole page. The tools are on Agents over MCP.
