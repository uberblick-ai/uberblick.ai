Charts and data tables

A document owns named collections of JSON records beside its prose. A chart or a data table is a few lines that say which collection and which fields. When an agent writes new records, every block that reads them refreshes, and nobody pastes a stale image again.

Source beside drawing

A chart pasted as an image is stale the day after. Here a document owns named collections of JSON records beside its prose, and a chart fence holds only the mapping: which collection, which fields. The values live in the records, so when an agent writes new ones with update_data, every chart and table that reads them refreshes, and the source stays a few lines of JSON that are easy to review.

```chart
{
  "version": 1,
  "type": "line",
  "title": "Pull requests per day",
  "collection": "pull_requests",
  "x": {"field": "day", "type": "date"},
  "y": [
    {"field": "opened", "label": "Opened"},
    {"field": "merged", "label": "Merged"}
  ]
}
```

A line chart takes one x field, a number or a date, and one to eight numeric y series with optional labels and units. layout: "panels" draws one small chart per series; missing decides whether a gap breaks or bridges a line. The same block with "type":"table" and up to thirty columns, each with a field and a text, number, date or link format, is a data table with sorting. Both omit records that fail the collection's schema and say how many they left out.

Where the numbers live

Each document has a data area: named collections, each with a JSON schema and records with an id and a value. Agents read it with get_data and write it with update_data, one validated batch per call: set the schema, replace or delete records, upsert whole records. Records that fail the schema are kept, marked invalid, and left out of every chart with a count of how many were skipped. From the terminal, ub data get <doc> <collection> prints a collection as JSON and ub data update <doc> --file ops.json applies a batch, which is how a script or an Action feeds a report.

Line, bar, table

  • Line: one x field, a number or a date, one to eight numeric series with labels and units. layout: "panels" draws one small chart per series; missing says whether a gap breaks or bridges the line.
  • Bar: the same mapping with "type":"bar"; several series draw as grouped bars, and a series can draw as bars behind lines. Series can carry their own axis range and reference lines.
  • Table: "type":"table" with up to thirty columns, each a field and a text, number, date or link format. Sortable in the editor.

The exact shape is in get_help("data"). Charts render in the editor and export as their source fence, so the numbers are never lost.
