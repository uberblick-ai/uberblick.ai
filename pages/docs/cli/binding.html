Project binding

There is no settings file to edit. Selection comes from the project, credentials from one private file, and two environment variables cover the cases where a process needs a different workspace than the directory it runs in.

Where selection comes from

  1. UB_WORKSPACE_ID and UB_HUB_URL in the environment. When set, they win for that process. UB_WORKSPACE_ID is required; UB_HUB_URL is a hub address, or local for a workspace with no hub, and is needed until this machine has a record of the workspace.
  2. The nearest .uberblick.json above the current directory. Written by ub workspace create and ub workspace use; commit it.
  3. Nothing. Commands that need a workspace say so and name the two ways to get one.

An environment binding still in force after you change the project file is reported, so a stale shell export does not surprise you. The legacy WORKSPACE_ID and HUB_URL are refused with a message.

Several workspaces for one agent

An MCP client can register the server more than once under different names, each entry with its own UB_WORKSPACE_ID and UB_HUB_URL in its environment. ub mcp install --print gives the entry to adapt. Each server process then serves one workspace, and the agent sees two servers with the same tools.

.mcp.json · two workspaces
{
  "mcpServers": {
    "uberblick": { "command": "ub", "args": ["mcp", "serve"] },
    "uberblick-design": {
      "command": "ub", "args": ["mcp", "serve"],
      "env": { "UB_WORKSPACE_ID": "9b71…", "UB_HUB_URL": "https://hub.example.com" }
    }
  }
}

Files and where they live

WhatWhere
Project binding.uberblick.json in the project, found by walking up from the current directory
Workspace databases~/.local/share/uberblick/<workspace-id>.sqlite, one per workspace, shared by every checkout on the machine
Login and device credential~/.config/uberblick/credentials.json, private to the user, never copied into an MCP entry
Client config~/.config/uberblick/config.json

XDG_CONFIG_HOME and XDG_DATA_HOME move the two directories on every platform; relative or empty values are ignored. macOS uses the same dot directories, not Application Support, so a backup script works unchanged on both.

Environment variables

VariableEffect
UB_WORKSPACE_IDSelect this workspace for the process, overriding the project file
UB_HUB_URLThe hub for that workspace, or local; only with UB_WORKSPACE_ID
BROWSERThe command ub open and ub auth login use to open a page; none prints the address instead
XDG_CONFIG_HOME, XDG_DATA_HOMEMove the config and data directories

Hub-side settings, such as the host name and the Tailscale route, live in the hub's .env and are on Run a hub.
