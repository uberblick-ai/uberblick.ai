Uberblick / Docs / CLI reference

ub open

ub open serves the web app on this computer and opens the project's workspace in the browser. It runs in the foreground until Ctrl-C, creates no daemon and no log files, and needs no separate hub to start or stop. The browser's workspace switcher shows this computer's other copies too; switching changes only the view, .uberblick.json still decides where agents write.

Usage

help
$ ub open --help
usage: ub open [options]

Serve the web app for this project's workspace, with a hub behind it, and open the browser. Runs until Ctrl-C.

options:
  --no-browser   # Print the address instead of opening a browser
  --port <n>     # Port for the web app (default 13379)
  --verbose      # Also print hub, sync and startup details for debugging

BROWSER names the command that opens the address; BROWSER=none works like --no-browser. If no browser opens, it warns and keeps serving.

What it starts

Terminal
$ ub open
web        http://127.0.0.1:13379/
workspace  Acme product (https://hub.example.com)

Ctrl-C to stop.

The prebuilt web app runs here, on 127.0.0.1 only, so it is never reachable from another machine. For a workspace on a hub nothing else starts: the browser syncs through this computer with the login from ub auth login. For a local workspace a local hub runs here too, on port 1234, unless one is already running. Its signing secret lives in ~/.config/uberblick/credentials.json, readable only by you and never printed; ub workspace create makes it along with the workspace, so agents started before the first ub open can already sync.

Others in the editor see you under git's user.name, falling back to your OS username, with a colour picked for you; both can be changed in the editor's preferences. The sidebar footer shows the GitHub handle the hub accepted, and follows ub auth login and logout without a restart. ub open prints only what you have to act on; --verbose adds the hub's events, the sync log and full error details for a bug report.

Exit codes

0 after Ctrl-C. 1 when it cannot start: no workspace, the port is taken, the secret file can be read by others, a web bundle in a checkout that is missing or out of date, or this computer recording a different hub for the workspace. 2 for a usage error.

Scenarios

Not signed in to the hub
The web app still opens and edits stay on this computer until you sign in, including after a credential expired at 30 days. The output adds hub not signed in, changes stay on this machine → ub auth login.
On a server, or over SSH
ub open --no-browser prints the address. On your own computer: ssh -L 13379:127.0.0.1:13379 server, then open it there.
Two projects at once
Each ub open needs its own web port: error: port 13379 is already serving Acme product, from another ub open → ub open --port 13380.
A secret others can read
ub open stops rather than fixing the permissions, because the secret may have leaked. Delete ~/.config/uberblick/credentials.json; the next ub open makes a new one. Then restart running agents, and sign in again if the file held hub logins.
No workspace in this project
no .uberblick.json here or in any parent directory → ub workspace create <name>, or ub workspace use <link|id>, exit 1.
After an update
Stop and start it; it keeps the version it started with. In a source checkout, run mise run build-web first; ub open never builds the web app.
