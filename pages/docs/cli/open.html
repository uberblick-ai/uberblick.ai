Uberblick / Docs / CLI reference

ub open

The browser editor is served by ub on your own computer, on the loopback address, for the workspace this project is bound to. It runs until Ctrl-C. There is no desktop app to install and no page on the hub to open.

Usage

help
usage: ub open [options]

options:
  --no-browser      print the address instead of opening a browser
  --port <n>        port for the web app
  --verbose         also print hub, sync and startup details

Open the editor

Terminal
$ ub open
serving Acme product at http://127.0.0.1:4800/
syncing with hub.example.com as ben

Opens the editor in your browser for the bound workspace. A hub workspace syncs in the background while the editor is open; a local-only workspace runs with a local hub that ub open starts for it. BROWSER in the environment names the command used to open the address, and BROWSER=none does what --no-browser does.

Scenarios

Over SSH
ub open --no-browser prints the address; forward the port and open it on your side. The editor binds loopback only, so it is never reachable from another machine.
Not signed in
A hub workspace still opens from the local copy and the footer says not shared with hub; ub auth login is the fix it names.
Two projects at once
Each ub open picks the next free port; --port pins one.
After an update
Stop and start ub open; it keeps the version it started with.
