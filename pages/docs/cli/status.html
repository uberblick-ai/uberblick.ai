Uberblick / Docs / CLI reference

ub status

One screen that says where this project's workspace is, where that selection came from, what is stored locally, and whether changes are reaching the hub. Each problem names its fix.

Usage

help
usage: ub status [--json]

options:
  --json            the same report as JSON on stdout, for scripts

The report

Terminal
$ ub status
workspace   Acme product (3f9c0a1e-…)
selected    ./.uberblick.json
storage     ~/.local/share/uberblick/3f9c0a1e-….sqlite, 1.2 MB
client      ub 0.4.8, protocol 7
hub         hub.example.com, protocol 7, signed in as ben
pending     0 changes
last sync   2 minutes ago

It connects briefly to the hub for a live answer. Last sync is the last full acknowledgement of this replica, not a promise about durable hub storage. A recent sign-in from another device is mentioned here, so a credential that walked off is noticed. When client and hub are on different protocol versions, the side that is behind reads update required.

Scenarios

Is my work on the hub?
pending 0 and a recent last sync say yes.
Which workspace is this directory using?
The selected line says whether the binding came from .uberblick.json or from UB_WORKSPACE_ID in the environment.
Something is wrong
The line in question names the fix; ub doctor runs the full checks.
