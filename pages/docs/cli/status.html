Uberblick / Docs / CLI reference

ub status

One report that says which workspace this project uses, where that selection came from, where the local copy lives and whether changes are reaching the hub. Each problem names what to run next. ub doctor is the deeper diagnosis.

Usage

help
$ ub status --help
usage: ub status [--json]

Show this project's workspace, selection source, local storage and sync status.

options:
  --json    # The same report as JSON on stdout, for scripts

The report

Terminal
$ ub status
workspace   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f)
hub         https://hub.example.com
version     client 0.4.8, hub 0.4.8
account     @octocat (GitHub)
chosen by   project config in ~/Projects/acme
stored in   ~/.local/share/uberblick/3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f.sqlite
connection  connected
pending     none
last sync   12 seconds ago
problems    none

It connects to the hub for a few seconds at most to get a live answer. Last sync means every change in the local copy was acknowledged by the hub; that is acknowledgement, not a promise about durable hub storage. Pending counts what the hub has not acknowledged yet. The connection line names the step that failed when one did: DNS, a refused or timed-out connect, TLS, the HTTP upgrade, or a close code from the hub. When signed in, it also lists other devices of your GitHub account that first signed in within the last seven days, with both ways to revoke them, so a credential that walked off is noticed.

Terminal
$ ub status
workspace   Research notes (9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c)
hub         local, this computer only
version     client 0.4.8
account     none needed for a local workspace
chosen by   project config in ~/Projects/notes
stored in   ~/.local/share/uberblick/9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c.sqlite
problems    none

A local workspace has no connection, pending or last sync lines.

Exit codes

0 whenever it could report, even with problems or pending changes; gate scripts on ub doctor instead. 1 when this project has no workspace. 2 for a usage error. --json prints one object with the same fields, pending.count always a number and lastSync in UTC.
