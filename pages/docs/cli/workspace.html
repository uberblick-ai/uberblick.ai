Uberblick / Docs / CLI reference

ub workspace

A workspace is one set of documents that you and the agents you connect read and write together. ub workspace creates workspaces, lists the ones on this computer, selects the one a project uses, publishes a local one through a hub, and manages who has access there. An agent started in a project writes into the workspace that project uses, so ub status is the quick check before handing work to an agent.

Usage

help
$ ub workspace
usage: ub workspace [command]

commands:
  create <name>    # Create a new local workspace. New workspaces always start locally
  list             # List all available workspaces on this machine
  use <link|id>    # Use a workspace in this project: a hub link someone shared, or a workspace from list
  remove <id|prefix> [--yes] # Delete this computer's copy of a workspace
  fork             # Create an independent local copy with a new workspace UUID
  promote <hub>    # Promote a local workspace to a remote hub
  member <command> # Grant and manage access to a workspace on a hub (admins only)

A bare ub workspace prints this help and never acts. create, use, fork and promote write the project's .uberblick.json; what that file holds and how it is found is on Project binding.

create

Terminal
$ ub workspace create "My Workspace"
created    My Workspace (b3eea2f9-a8dc-40f2-a3d9-b27742620b1f, local)
wrote      ~/Projects/notes/.uberblick.json
previous   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f, https://hub.example.com)
switch back with: ub workspace use 3f0c2a1e
open it with: ub open

Seeds a new local workspace with a few starter documents and binds the current directory to it. No hub, no login. When it replaces a binding it names the previous workspace and the command that switches back. Promotion to a hub can come later; the id and the history stay the same.

list

Terminal
$ ub workspace list
* 3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f | Acme product     | https://hub.example.com
  9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c | Research notes   | local

Every workspace this computer has a copy of, with the one this project uses marked. The last field is the hub this computer syncs it with, or local. It reads the local copies only and works offline. With no binding in reach it still lists them and notes No workspace selected (no .uberblick.json found). --json for scripts.

use

Terminal
$ ub workspace use 9b71d0c4
using      Research notes (9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c, local)
wrote      ~/Projects/notes/.uberblick.json
previous   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f, https://hub.example.com)
switch back with: ub workspace use 3f0c2a1e

Selects this project's workspace and writes the binding. An id, or a unique prefix of one, selects a copy this computer already has. A hub link, https://hub.example.com/<workspace-id>, fetches the workspace from that hub first; it needs a prior ub auth login and says so instead of starting one. A document address from the browser is not a workspace link. Two workspaces are never merged, and the browser's workspace switcher changes only the view; this binding decides where agents write.

fork

Terminal
$ ub workspace fork
forked     Acme product (c81e2f4a-5d6b-4e7f-8a9b-0c1d2e3f4a5b, local)
wrote      ~/Projects/notes/.uberblick.json
previous   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f, https://hub.example.com)
switch back with: ub workspace use 3f0c2a1e

Copies the selected workspace into an independent local one with a new id and the same name and documents, local changes and archived documents included, and selects the copy. The source is untouched and no sign-in is needed. Rename the fork in the editor's workspace settings; publish it with promote.

promote

Terminal
$ ub auth login https://hub.example.com
$ ub workspace promote https://hub.example.com
uploading  My Workspace (b3eea2f9-a8dc-40f2-a3d9-b27742620b1f) to https://hub.example.com
verified   42 documents, including archived ones
promoted   My Workspace (b3eea2f9-a8dc-40f2-a3d9-b27742620b1f, https://hub.example.com)
wrote      ~/Projects/notes/.uberblick.json
share link: https://hub.example.com/b3eea2f9-a8dc-40f2-a3d9-b27742620b1f
commit .uberblick.json so teammates only need ub auth login

Uploads the local workspace to a hub as it is: same id, same history, archived documents included. The upload is verified before the project is switched to the hub copy. It needs a sign-in and the account must be a hub admin; the uploader becomes the workspace's admin. Without a sign-in nothing is uploaded and the workspace stays local. Interrupted? Run it again and it resumes. Promote is not a switch, so there is no switch-back line; it prints the share link to pass on.

member

help
$ ub workspace member
usage: ub workspace member <command>

commands:
  add <github-handle> [--role admin|member] [--yes]  # Confirm the GitHub account, then grant access
  list [--json]                              # Members, their account IDs and roles
  role <member> <admin|member>               # Change a member's role
  remove <member>                            # End a member's access on every device
Terminal
$ ub workspace member add dana
Grant access on https://hub.example.com to workspace 3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f for "dana" (GitHub account 480938) as member? [y/N] y
added "dana" (GitHub account 480938) as member
Access is discovered on sign-in or credential renewal; select the workspace explicitly with `ub workspace use https://hub.example.com/3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f`.
$ ub workspace member list
hub https://hub.example.com; workspace 3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f

"octocat" (GitHub account 371)   | Octo Cat   | admin
"dana" (GitHub account 480938)   | Dana Lee   | member

Access to a shared workspace, managed by a workspace admin with an existing sign-in. Members are GitHub accounts; there are no Uberblick accounts, and belonging to a GitHub organisation or repository grants nothing. add looks the handle up on GitHub and asks before granting; --yes confirms in scripts. The grant is immediate, needs no acceptance, and is bound to the permanent account id, so a renamed handle keeps its access. remove ends access on every device without signing anyone out; documents already on their disk stay there. The last admin cannot be demoted or removed. A local workspace has no members: member list says so and exits 1.

Two roles in a workspace. A member reads and writes every document, in the browser and over MCP; reading and writing are not separate rights. A workspace admin also manages members and the workspace settings. A third role lives on the hub: the hub admin sees every workspace on it, suspends and restores them, and is the only one who can promote a new workspace onto it. It grants no document access by itself. The first account to sign in on a fresh hub holds it; the operator appoints more with ub-hub hub-admin add, see Run a hub.

remove

Terminal
$ ub workspace remove 9b71d0c4
Delete this computer's copy of workspace 9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c? This is the only copy of this local-only workspace. [y/N] y
removed 9b71d0c4-2e5f-4a8b-b3c6-1d2e3f4a5b6c from this computer

Deletes this computer's copy of one workspace and nothing else: hubs, bindings and logins stay. A workspace on a hub can be fetched again with use and its link, which the prompt repeats; changes the hub has not acknowledged are lost, and the prompt warns about them. For a local-only workspace this is the only copy. The selected workspace and one that ub open is serving cannot be removed; --yes skips the question and is required without a terminal. Agents with the workspace open refuse writes until restarted.

Scenarios

Start alone, share later
create today, work locally, promote when a second person arrives. Then commit .uberblick.json.
Join a workspace a colleague shared
With the committed binding: clone, ub auth login, which reads the hub from the file, and ub status. Without it: ub auth login <hub>, then ub workspace use with the link they sent.
Give a colleague access
ub workspace member add dana --yes; they sign in and select the link. Access is discovered on sign-in, so an account that was already signed in sees the workspace at its next credential renewal or login.
Check which workspace an agent will write to
ub status in the project directory. The browser switcher does not change it.
Try something without touching the shared workspace
fork, experiment, then promote the fork under a new name or remove it.
Someone leaves
member remove ends their access on every device. Their local copy stays on their disk; revocation cannot reach into a computer.
