Uberblick / Docs / CLI reference

ub mcp

The MCP server is how an agent reads and writes the workspace. ub mcp install registers it with the agent's client by running that client's own mcp add, so the vendor writes its own file. The entry is a plain ub mcp serve; the server follows the project binding where the agent starts.

Usage

help
usage: ub mcp [command]

commands:
  install <client>   register Uberblick with an agent's MCP client: claude or codex

options for install:
  --user             register for every project of this user, not just this project
  --print            print the entry to paste, and run nothing

install

Terminal
$ ub mcp install claude
registered uberblick with Claude Code for this project: ub mcp serve

Clients today: claude and codex. A second run reports already installed; an entry named uberblick that ub did not write is left alone and reported. --user registers for every project of this user instead of this one. Any other client gets the generic stdio snippet with --print, to paste into that client's own configuration. Install needs no workspace and no login; credentials stay in the private user store and are never copied into an entry.

serve

ub mcp serve is the server itself, started by the client. You do not run it by hand. It serves the workspace of the nearest .uberblick.json above the agent's working directory, or the one named by UB_WORKSPACE_ID in the entry's environment, see Project binding. Restart the client after an update; a running server keeps the version it started with.

Scenarios

Set up a new project
ub workspace use or create, then ub mcp install claude in the same directory. Both are committed through .uberblick.json and the client's project config.
One agent, two workspaces
Register the server twice under different names, each entry with its own UB_WORKSPACE_ID and UB_HUB_URL. --print gives the entry to adapt.
Another client
ub mcp install cursor --print prints the stdio entry to paste.
