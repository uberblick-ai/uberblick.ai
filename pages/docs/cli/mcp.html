Uberblick / Docs / CLI reference

ub mcp

ub mcp connects an agent to this project's workspace. After install, every agent started in the project reads and writes documents through the Uberblick MCP tools. The server itself is ub mcp serve; the client starts it, you never do.

Usage

help
$ ub mcp
usage: ub mcp [command]

commands:
  install <client>   # Register Uberblick with an agent's MCP client: claude or codex

options for install:
  --user             # Register for every project of this user, not just this project
  --print            # Print the entry to paste, and run nothing

install

Terminal
$ ub mcp install claude
ran        claude mcp add --scope project uberblick -- ub mcp serve
wrote      ~/Projects/notes/.mcp.json (by Claude Code)
workspace  follows ~/Projects/notes/.uberblick.json
restart running agents to pick it up

The client is required, there is no default. For claude and codex it runs that client's own mcp add, so the vendor writes its own file; ub never edits a client config itself. The entry is a plain ub mcp serve named uberblick with no environment, so agents follow the nearest .uberblick.json and a later ub workspace use moves all of them at once. Install needs no workspace and no login; without a binding it still registers and warns that agents cannot start until one exists. Running it again changes nothing. An uberblick entry that ub did not write is left alone, with the client's remove command named. There is no uninstall: claude mcp remove --scope project uberblick, or the Codex equivalent.

Terminal
$ ub mcp install codex --user
ran        codex mcp add uberblick -- ub mcp serve
workspace  follows the nearest .uberblick.json of each project

--user puts the entry in the client's per-user config. It still follows the binding of whichever project the agent starts in.

serve

ub mcp serve reads the nearest .uberblick.json owned by you when it starts, or UB_WORKSPACE_ID from the entry's environment, see Project binding. Without either it refuses to start and says so in the client's MCP log. A running server keeps its workspace, so restart the agent after ub workspace use, and after an update. For a hub workspace it uses this computer's login and renews the credential itself; after 30 days without renewal the hub refuses it and sync_status says to sign in again, while local documents stay usable. On shutdown it waits up to 12 seconds for the hub to acknowledge pending changes and otherwise reports how many stay local.

Exit codes

For install: 0 when the entry is registered, already ours, or printed with --print. 1 when nothing got registered: the client is missing or its command failed, and the entry is printed to paste by hand; or an entry someone else wrote is in the way. 2 for a usage error, including a missing client.

Scenarios

Set up a new project
ub workspace use or create, then ub mcp install claude in the same directory. Both files are committed: .uberblick.json and the client's project config.
Client not installed
error: claude not found on PATH, the entry to paste is printed, exit 1. Install Claude Code and run it again.
An entry someone else wrote
The command names the file and the entry it found, leaves it alone and exits 1. Remove it with claude mcp remove --scope project uberblick, then install again.
A client ub does not know
ub mcp install cursor --print prints { "mcpServers": { "uberblick": { "command": "ub", "args": ["mcp", "serve"] } } } to paste into that client's configuration.
The agent has no Uberblick tools
ub doctor reads the known clients' project and user configs and says which one is missing. Fix what it reports, then restart the agent.
