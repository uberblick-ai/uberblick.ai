Uberblick / Docs / CLI reference

ub auth

A local workspace needs no login. Sharing one does: ub auth signs this computer in to a hub with GitHub's device flow and stores a credential for this computer only. Nothing is copied into an MCP entry, and no command ever starts a sign-in on its own.

Usage

help
usage: ub auth [command]

commands:
  login [hub]            sign in to a hub with GitHub
  status [hub] [--json]  check the stored login and current hub administration
  logout [hub]           sign this computer out; --all-devices signs out all of yours

login

Terminal
$ ub auth login https://hub.example.com
Open https://github.com/login/device and enter the code ABCD-1234
… signed in as ben; this computer holds a device credential for hub.example.com

Open the address, enter the code, done. The command completes on its own and never asks for keyboard input; in a local terminal the approval page opens by itself, over SSH only the address and code are printed. The hub learns your GitHub login and nothing else. The credential belongs to this computer, expires after 30 days and renews itself while in use. Without a hub argument the project's bound hub is used. Signing in grants no workspace access by itself; a workspace admin does that with ub workspace member. On a fresh hub the first login claims it and makes that account the hub admin.

status

Terminal
$ ub auth status
hub.example.com accepts this computer's login as ben
hub admin: yes

One read-only request: does the hub still accept the stored login, and is this account a hub admin. Exit 1 means the hub could not answer, not that you are not an admin. --json prints one object for scripts.

logout

Terminal
$ ub auth logout
$ ub auth logout --all-devices https://hub.example.com

Revokes this computer on the hub and removes its login here. With --all-devices every device of your account on that hub is revoked, this one last; that is how a lost laptop is handled from any computer still signed in. Workspace memberships, the project binding and the local workspace copies stay.

Scenarios

A teammate joins a shared workspace
They install ub, run ub auth login with the hub, and an admin grants them access. Then ub workspace use with the link fetches the workspace.
An agent host or an Actions runner
It signs in once like any other computer and holds its own credential, which can be revoked on its own. An agent uses the login of the computer it runs on.
A hub says the login is not accepted
ub auth status says why. A credential older than 30 days that the hub refuses is removed; sign in again.
A laptop is lost
From any computer that is still signed in: ub auth logout --all-devices, then sign the remaining computers in again.
