Uberblick / Docs / CLI reference

ub auth

ub auth signs this computer in to a hub so it can sync shared workspaces. A local workspace needs no sign-in. No command ever starts a login on its own: one that needs it stops and names ub auth login.

Usage

help
$ ub auth
usage: ub auth [command]

commands:
  login [hub]            # Sign in to a hub with GitHub
  status [hub] [--json]  # Check the stored login and current hub administration
  logout [hub]           # Sign this computer out of a hub; --all-devices signs out all of yours

A bare ub auth prints this help and does nothing. Each subcommand takes a hub address; without one it uses the hub of this project's binding. A hub on another computer must be https:// or wss://; a cleartext address is refused before anything is sent, with the secure form named.

login

Terminal
$ ub auth login https://hub.example.com
hub        https://hub.example.com
open       https://github.com/login/device
code       WDJB-MJHT
waiting for approval…
signed in  octocat on https://hub.example.com
available workspaces:
  3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f | Acme product
  4f0b9c2e-7a1d-4e6b-9c35-8d2e1f6a0b47 | Design reviews

Open the address, enter the code, approve. The terminal finishes on its own; GitHub names the Uberblick app, not the hub. The hub learns your GitHub login and nothing else. Login does not change the project binding and does not download every workspace: the next step is usually ub workspace use with a link, unless the repository already carries a .uberblick.json, in which case nothing more is needed.

The credential belongs to this computer. It lasts 30 days and renews itself after 15 while anything syncs, without another GitHub approval. Signing in grants no workspace access by itself; a workspace admin does that with ub workspace member. On a fresh, unclaimed hub the first login claims it: that account becomes hub admin and admin of the default workspace, and login warns before the approval so you do it before anyone else can.

status

Terminal
$ ub auth status https://hub.example.com
hub        https://hub.example.com
stored account  octocat (github)
stored available workspaces:
  3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f | Acme product
hub's current answer:
login (hub)  accepted
hub admin (hub)  no

The stored login and the workspaces it knew at the last sign-in, then one read-only question to the hub: is this login still accepted, and is the account a hub admin. It never renews or writes anything. Exit 0 for a confirmed answer either way, including a local binding with no hub; exit 1 when the hub could not confirm, which is not the same as not being an admin. --json prints the same report as one object.

OutcomeExitNext step
hub-admin, not-hub-admin0None
no-hub0Local work needs no login; name a hub to check one
not-signed-in, login-refused1ub auth login <hub>
update-required1Update the side the message names
hub-unreachable, hub-error1Check the network, or ask whoever runs the hub

logout

Terminal
$ ub auth logout
$ ub auth logout --all-devices https://hub.example.com

Revokes this computer on the hub and removes its login here. Sync with that hub stops; workspace copies, memberships and the project binding stay. With --all-devices every device of your GitHub account on that hub is revoked, this one last. If the hub cannot be reached, nothing is revoked and the login is kept, exit 1; a revocation the hub could not confirm still removes the login and says the computer is not yet revoked, to be finished from another signed-in computer.

Scenarios

Signed in, but the workspace is missing
Your account may have no grant yet, or the hub has suspended the workspace. Ask a workspace admin to add your GitHub account, or a hub admin to restore it. Sync picks up new access without another login.
Claim a fresh hub
Sign in before anyone else can. After the claim, login offers the complete ub workspace use command for the default workspace; running it writes the binding. Login never binds on its own.
Retire a lost or passed-on computer
If you still have it, log out there. Otherwise ub auth logout --all-devices <hub> from any computer with a valid login, then sign back in on the ones you keep.
A computer was away for more than 30 days
Its credential expired with no grace period. ub open and agents keep working on the local copy; ub auth login again and the pending changes reach the hub.
An agent host or an Actions runner
It signs in once like any other computer and holds its own credential, which can be revoked on its own. An agent can also use its own GitHub account; the grant rules are the same.
