ub doctor

Eight checks on the project you run it in, each with the fix spelled out: the workspace binding, the local database, the stored login, the hub, the clock, and whether an MCP client is registered for this project. Checks that cannot run yet say why.

Usage

help
usage: ub doctor [--json]

options:
  --json            the same checks as JSON on stdout, for scripts

Run it

Terminal
$ ub doctor
✓ workspace   Acme product, from ./.uberblick.json
✓ database    ~/.local/share/uberblick/<workspace-id>.sqlite
✓ login       ben at hub.example.com
✓ hub         reachable, protocol 7
✓ clock       within 2 s of the hub
! mcp         MCP client is not set up for this project
              fix: ub mcp install claude

Exit 0 when every check passes, 1 otherwise. --json prints the same checks as one object, which is what a setup script or an agent reads.

Scenarios

A new computer
Run it after ub workspace use; it walks you through login and MCP registration one fix at a time.
The agent cannot write
A clock that is off against the hub or a refused login shows up here before you look anywhere else.
