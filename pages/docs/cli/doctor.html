ub doctor

ub doctor checks whether Uberblick works in this project and, for each problem, names the command that fixes it. Run it when an agent or the web app says offline, or when something will not sync. It only looks; it never repairs, creates or changes anything.

Usage

help
$ ub doctor --help
usage: ub doctor [--json]

Check this project's Uberblick setup and name the fix for each problem.

options:
  --json    # The same checks as JSON on stdout, for scripts

Output

Terminal
$ ub doctor
uberblick 0.4.8

ok    workspace   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f), from ~/Projects/acme/.uberblick.json
ok    login       octocat on https://hub.example.com
ok    database    ~/.local/share/uberblick/3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f.sqlite
ok    hub         connected to https://hub.example.com; octocat has access
ok    clock       within 2s of the hub
skip  local hub   no local hub is used; this workspace syncs through https://hub.example.com
skip  web server  127.0.0.1:13379 is not running; ub open starts it
ok    mcp         Claude Code (.mcp.json)

0 failed, 0 warnings, 6 passed, 2 skipped

Eight checks, each one line: ok, warn, FAIL or skip, its name and what it found. A warning or failure adds an indented line with what to do. Checks after a failed one still run, so one run shows every problem. A check that does not apply is skipped and says why: for a local workspace, login, hub and clock are skipped and the local hub is checked instead.

CheckWhat it answers
workspaceDoes this project use a workspace, and which one?
loginFor a workspace on a hub: is this computer signed in to that hub?
databaseCan this computer read and write its copy of the workspace?
hubDoes the hub answer, and does this login have access to the workspace?
clockIs this computer's clock close enough to the hub's for sign-in to work?
local hubFor a local workspace: is its hub running on the port the browser and agents use (default 1234)?
web serverIs the web app from ub open running on 127.0.0.1:13379?
mcpIs an agent's MCP client set up for this project?

Exit codes

1 when any check fails, 0 otherwise, warnings included, so it works as a gate in scripts. Two things are warnings, not failures: a hub that cannot be reached, because work continues on this computer and syncs once the hub is back; and a missing MCP setup, because Uberblick works without agents. --json prints one object with the eight checks in a fixed order, each with name, status, reason and fix.

Scenarios

An agent or the web app says offline
Offline can mean the hub is unreachable, the login is missing or refused, or the clock is off. They look the same in the web app; doctor tells them apart: warn hub timed out after 1.5s connecting to 203.0.113.7:443 is a warning, a refused login or a clock out of step is a failure.
No workspace in this project
FAIL workspace no .uberblick.json here or in any parent directory → ub workspace create <name>, or ub workspace use <link|id>.
Signed in, but no access to the workspace
FAIL hub octocat has no access to the workspace, or it doesn't exist on this hub → ask a workspace admin to run: ub workspace member add octocat.
Clock out of step
Sign-in proofs live for 60 seconds, so a clock that is minutes off makes the hub refuse every request. FAIL clock 4 min ahead of the hub → turn on automatic time in your system settings.
Agent not connected
warn mcp MCP client is not set up for this project → ub mcp install claude (or codex). Fix it, then restart the agent.
