Document history

Agents edit pages while you are away. The history shows what changed since you last looked, who changed it, and whether it was a person in the browser or an agent over MCP. Every revision of a page on a shared workspace is kept, and you read any of them beside the one before it.

Step back from the revision id

Under the title, beside the revision id, ‹ opens the history and steps to older revisions; › steps forward again. The sidebar turns into the list of revisions, newest first, each with its author, where the edit came from (the browser or an agent's client) and when. Click an entry to jump straight to it. Back to now returns to the live page. History is read-only: nothing you click there changes the page.

Before on the left, after on the right

A revision shows beside the one before it. Removed text is red on the left, added text green on the right, and a hatched gap holds the place of a block that exists on one side only. Inside a changed paragraph only the changed words are marked, so a one-word fix reads as one word.

Unchanged blocks fold into a bar that names the headings inside it, such as 18 unchanged blocks · Default to the framework, Always holds. A click opens that run; Collapse unchanged in the sidebar opens them all. A slim ruler at the right edge marks where the changes are on the page, and the arrows above it jump to the previous or next change. When the title changed, the header says what it was renamed from.

JSON compares by structure

A JSON tree that changed spans both columns, with the earlier rows on the left and this revision's on the right. Formatting and key order never count as changes. List items match by their id, key or name, so a new item shows as one addition and an item that only moved says moved from [2]. Only changed values are tinted, unchanged parts fold away, and Expand opens the comparison full screen with search across both sides. A changed diagram shows its full drawing on each side, so the change is visible in the picture itself.

What a revision is

Revisions are made for you; there is nothing to save. One revision is one author's stretch of editing: it ends when someone else edits the page, or after fifteen minutes. So the list reads as what each person or agent did, not as a log of keystrokes. The hub keeps the revisions, so history needs a shared workspace; a local-only workspace has none.

Name the revisions that matter

The small tag icon before the revision id names the current state of the page: type a name, press Enter, or Escape to cancel. A named revision shows its name where the id would be, and the Named tab in the history sidebar lists only those. Name the state you reviewed with the team, or the one a release shipped with, and you can always step back to exactly that text. Whoever named a revision can rename it later, or clear the name to remove it.

Over MCP, list_revisions returns a page's revisions, newest first, and get_revision reads the page as it was at one of them. An agent uses them to see what changed since it last worked on a page, or to quote what a page said when a decision was made. name_revision names the current state, and is meant for when a person asks for it. The tools are on Agents over MCP.
