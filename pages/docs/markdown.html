Markdown baseline

Markdown is a good standard, and GitHub extended it in ways that stuck. It still has one blind spot: agents produce long walls of text that nobody scans. Uberblick looks for the few additions that let an idea be drawn instead of described, a flow, a screen, a chart, and publishes each one as its own package so you can use it without Uberblick. All of them stay text. An agent writes a block over MCP, a person edits it in the browser, and export_markdown gives the document back as a file that any Markdown tool can still open. You do not have to teach your model any of this: the Uberblick MCP server carries the syntax of every block as a help topic, so an agent asks get_help("markdown") and writes it right.

What stays standard

Common standard Markdown, headings, lists, quotes, code and inline formatting, plus GitHub Flavored Markdown tables and strikethrough, reads and writes as everywhere else. A link whose target is a document id, [label](document-uuid), links to that document, survives renames and counts as a backlink; agents get the id from search or get_sidebar and never guess it from a title. The additions below take one of two shapes: a fence with an info string for source a program reads, or a :::name container for prose with a header. Anything that does not know a shape sees a code block or a paragraph, which is the point.

The additions

Each has its own page with the source beside the drawing.

  • diagramsFlow diagrams as text where the author places the nodes and the renderer only draws.Replaces Mermaid.
  • wireframesA screen sketch in a few lines of text, drawn by the editor.Format 0.x; it may still change.
  • chartsLine and bar charts and generated data tables, drawn from records stored in the document.When an agent updates the records, every view updates with them.
  • embedsA live Figma file, frame, prototype or board, with a caption.Neither the hub nor ub ever contacts Figma.

Reading and writing it

Over MCP, get_doc returns the blocks with their ids, types, source text and revisions; insert_block writes an ordered array of blocks in one call, and edit_block writes one block against the revision it read; export_markdown writes the document as one Markdown file in these forms, and the CLI's ub data get and ub data update read and write the records a chart draws. The same syntax this page shows is served to the agent by get_help("markdown"), version-matched to the server it talks to, so a prompt never needs to carry it. Decision records are not Markdown additions but a kind of document, with their own tools; they are on Decisions.
