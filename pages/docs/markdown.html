Markdown baseline

Markdown is a good standard, and GitHub extended it in ways that stuck. Its blind spot: agents produce walls of text that nobody scans. Uberblick adds the few blocks that let an idea be drawn instead of described, a flow, a screen, a chart, each published as its own package. All of them stay text. An agent writes a block over MCP, a person edits it in the browser, and export_markdown gives back a file any Markdown tool opens.

What stays standard

Common standard Markdown, headings, lists, quotes, code and inline formatting, plus GitHub Flavored Markdown tables and strikethrough, reads and writes as everywhere else. A link whose target is a document id, [label](document-uuid), links to that document, survives renames and counts as a backlink; agents get the id from search or get_sidebar and never guess it from a title. The additions below take one of two shapes: a fence with an info string for source a program reads, or a :::name container for prose with a header. Anything that does not know a shape sees a code block or a paragraph, which is the point.

Reading and writing it

In the browser it is the editor you know from most wiki and knowledge base pages: headings, lists, tables, the blocks above, comments. It should feel familiar on the first page. Over MCP we spend a lot of our effort on token usage: an agent fetches only the parts of a document it needs and updates only those, instead of rereading or rewriting whole pages, and it gets the block syntax from the server when it needs it rather than from your prompt. You see what agents do in the web UI as it happens, their edits and their presence, the same way you see a colleague's. Decision records are not Markdown additions but a kind of document of their own; see Decisions.
