Read before you write

Telling an agent to read the principles page does not make it read the principles page. Uberblick moves the rule from the prompt into the server: pages tagged as guidance must have been read before any write, and a write that comes too early is refused with the list of what is unread.

Mark the pages

In workspace settings, choose the tag that marks guidance; by default it is guidance. Tag the pages an agent must never work without: the product principles, the writing rules, the page that says what the product does not do. Three to six pages is the right number. A page tagged guidance is still an ordinary page; the tag only puts it on the required reading list.

What the refusal looks like

The first write from a fresh MCP session fails. The failure is a normal tool error with a code, a sentence and the unread pages by id and title, so the agent knows exactly what to do next.

edit_block · refused
{
  "code": "guidance_required",
  "message": "Read the workspace guidance before changing documents.",
  "unread": [
    { "uuid": "7c1e…", "title": "Product principles" },
    { "uuid": "a90f…", "title": "Web UI: typography" }
  ]
}

The agent reads each page with get_doc and calls the write again. Nothing was written by the refused call. Every agent we have run handles this without instruction, because the error says what it wants.

The ten-minute lease

Completing the reads starts a lease in that server process: for ten minutes every write goes through, even if the guidance changes meanwhile. After that, fresh reads of the current guidance are required again, so an agent that works for an hour re-reads the pages a few times and picks up edits a person made in between. Restarting the server discards the lease. The lease is per process, so two agents in two terminals each read for themselves.

The briefing

Besides the pages, the server carries a short briefing that explains this rule and the shape of its failures, and get_help returns it under the orientation topic. The refusal points there too. Reads are never gated: get_doc, search, get_data and the rest work from the first call, so an agent that only reads is never slowed down.

What it does not do

It does not check that the agent understood the pages, and it cannot. It makes sure the pages were in the context when the write happened, which is the part a prompt cannot guarantee. Judgement stays with the reviewer, and with the decision records an agent is told to consult for the issue it works on.
