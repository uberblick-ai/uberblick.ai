CLI reference

The ub client has eight commands. Three principles hold across all of them: a bare command prints its help and never acts; a command that needs a login stops and tells you to sign in, and never starts a sign-in itself; anything that reports takes --json for scripts.

All commands

ub --help
auth login [hub]                     sign in to a hub with GitHub
auth status [hub] [--json]           check the stored login and hub administration
auth logout [--all-devices] [hub]    sign this computer out of a hub

workspace create <name>              create and select a local-only workspace
workspace use <link|id>              fetch a shared workspace or select a local one
workspace list [--json]              workspaces this machine has a database for
workspace fork                       copy this workspace independently and select the copy
workspace promote <hub>              upload, verify and connect this local workspace
workspace remove <id|prefix> [--yes] delete this computer's copy of a workspace
workspace member add|list|role|remove   grant and manage access as a workspace admin

mcp install <client> [--user] [--print]   register the server with claude or codex
mcp serve                            the MCP server itself, run by the client

open [--no-browser] [--port n] [--verbose]   serve the editor for this project
status [--json]                      workspace, selection source, storage, versions, sync
doctor [--json]                      check the setup and name the fix for each problem
data get <doc> [<collection>]        print a document's data summary or one collection
data update <doc> --file <path|->    apply update_data operations from a file
update                               update a Homebrew installation

auth

login opens GitHub's device flow for the given hub or the project's hub and stores a device credential for this computer; on a fresh hub the first login claims it. status makes one read-only request and says whether the stored login is accepted and whether you are a hub admin; exit 1 means the hub could not answer, not that you are not an admin. logout revokes this computer, or every device with --all-devices. Local-only work needs no login. Details: Access and membership.

workspace

create and use both end by writing the binding into the nearest .uberblick.json, or a new one in the current directory. use takes a hub link with the workspace id as its last segment, a workspace id, or a unique prefix of one this machine already has; it fetches, verifies, then binds, and never merges two workspaces. fork and promote are described on Workspaces. member add asks for confirmation; pass --yes without a terminal. remove deletes only this computer's copy.

mcp

install claude or install codex runs the client's own mcp add with a plain ub mcp serve entry named uberblick, for this project or, with --user, for every project. It edits no file itself, reports already installed on a second run and never replaces an entry it did not write. Any other client gets the snippet with --print. serve is what the client runs; you do not start it by hand.

open, status, doctor

open serves the editor for the bound workspace with a hub behind it and opens the browser; it runs until Ctrl-C, prints the address only with --no-browser, and --verbose adds hub, sync and startup details. BROWSER=none in the environment does the same as --no-browser. status connects briefly to the hub for a live answer and prints the workspace, where its selection came from, local storage, the client and hub versions and the last full sync acknowledgement; each problem names its fix. doctor runs the full checks: workspace, database, login, hub, clock and MCP registration.

data

get prints a document's data summary, or one collection as JSON, to stdout or --out. update applies a file of update_data operations, - for stdin, and --dry-run validates without writing. update skips the guidance reads that MCP writes require, which is why it is a terminal command for scripts and not an agent tool. See Charts and data tables.

update

Runs brew update and brew upgrade for the copy of ub on your path. A source checkout is left alone. See Install and update.

Exit codes and output

0 is success or a confirmed answer, 1 is a failure or an answer the hub could not confirm, 2 is a usage error. Reports go to stdout, warnings to stderr, and --json prints exactly one JSON object on stdout and nothing else there.
