Markdown extensions

Four small additions and one container. Each is still text that any Markdown tool shows as something sensible, and an agent learns all of them from get_help("markdown").

Links by id

[label](document-uuid) links to a document by its id. It survives renames and counts as a backlink on the target. Agents get the id from search or get_sidebar and never guess it from a title.

GitHub references

A link to an issue or pull request on GitHub renders as a compact pill with its number, and a decision record that links an issue is found by find_decisions for that issue. The pill does not fetch the issue; it is a reference, not a tracker.

Inline icons

A curated set of shortcodes, such as :check: or :warning:, renders as icons in prose and in card labels. An unknown shortcode stays text.

Terminal transcripts

A terminal fence keeps prompt, command and output apart, so a transcript reads as one and copies as the command only. It exports as the same fence.

Markdown
```terminal
$ ub status
workspace   Uberblick product, from ./.uberblick.json
```

Cards

A report that ends in "we recommend" loses the recommendation in the paragraph above it. A card gives it a shape: an optional label, a required title, an optional body and footer, and link buttons. Agents use it for the one thing a reader should act on, and a button can open the discussion straight in Claude Code or Codex.

:::card
label: Recommendation
title: Cut the retry limit to two
footer: From the delivery report of 16 October
button: [Discuss in Claude Code](claude://code/new?prompt=Review%20the%20retry%20limit) filled blue
button: [Open the issue](https://github.com/uberblick-ai/uberblick-2/issues/1588)

Three of this week's wasted runs were third retries on the same failure. A limit of two would have stopped each one a run earlier.
:::

Header lines are label:, title:, footer: and button:, in any order; the first blank line ends the header and the rest is the body. A button is one Markdown link to an https:// address or to claude://code/new, claude-cli://open or codex://new, followed by an optional style (outline or filled) and colour (neutral, blue, green or violet).

When to use one

For the one thing on a page a reader should act on: the recommendation at the end of a report, the warning at the top of a runbook, the next step after a review. One card per page is the norm; a page full of cards is a list wearing boxes. Agents that write reports put the card last and link the issue or the record it rests on in the footer.
