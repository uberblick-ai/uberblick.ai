Markdown extensions

We keep looking for small additions that make a page easier to read for people. Each is still text, so any other Markdown tool shows something sensible: the toggle marker, the shortcode or the transcript as they are. Here are a few examples.

Toggle headings

A heading that starts with > and a space, such as ## > Help text, folds everything below it until the next heading of the same or a higher level. Each toggle starts collapsed when the page opens; the open state stays in that view and is never saved. The heading stays ordinary text, so MCP, search and Markdown keep it and other viewers show the >.

Inline icons and emoji

A curated set of shortcodes, :claude:, :codex: and :github:, renders as the mark in prose, headings, table cells, callout icons, card parts and button labels, in the size and colour of the surrounding text. The stored text stays the shortcode. An unknown name such as :rocket:, and a time such as 10:30:15, stay literal. Emoji are stored as the character itself; in the editor a colon and two letters open a picker.

Terminal transcripts

A terminal fence replays a transcript: lines that start with $ and a space are commands, the rest is output. It never runs anything. Playback loops with a pause control, and reduced motion shows the static transcript. Import, export and MCP keep the literal text.

$ ub status

Callouts

Some sentences must not be skimmed past: a precondition, a risk, a step that cannot be undone. A callout sets one such passage apart from the text around it. It is GitHub's alert syntax, a quote whose first line names the variant, so GitHub shows the same text as an alert and any other Markdown tool shows a quote that still starts with its label.

> [!WARNING]
> Every browser and every `ub` client is signed out at once.
> Tell the team before you start.

There are five variants. Pick the one that says what happens if a reader skips the passage.

VariantSkipping it means
[!NOTE]The reader misses useful context.
[!TIP]The reader misses an easier or better way.
[!IMPORTANT]The reader will not succeed.
[!WARNING]Something breaks, or work is lost.
[!CAUTION]An action cannot be undone.

Each variant has its own colour and icon, and the label is always written out, so colour is never the only cue. A callout can swap the icon for an emoji or one of the inline icons above; the label and colour stay with the variant. In Markdown the icon is an HTML comment on the line after the marker, which other Markdown tools hide.

> [!TIP]
> <!-- icon: :claude: -->
> Ask Claude Code to draft the release notes from the merged pull requests.

Write one to three sentences that stand on their own, without "Note:" or "Warning:" in front, since the label already says it. A couple per page is plenty; two in a row, or a whole section in a box, and readers stop seeing them. The one thing a reader should act on belongs in a card, and a lasting choice in a decision record.

The marker stands alone on the first line, in any letter case; export writes it in uppercase. Anything else stays an ordinary quote: another name such as [!INFO], a title after the marker, a fold marker or a nested quote. Over MCP a callout is a block of type callout with a variant and an optional icon; an invalid one is refused with invalid_callout and nothing is written.

Cards

A report that ends in "we recommend" loses the recommendation in the paragraph above it. A card gives it a shape: an optional label, a required title, an optional body and footer, and link buttons. Agents use it for the one thing a reader should act on, and a button can open the discussion straight in Claude Code or Codex.

:::card
label: Recommendation
title: Cut the retry limit to two
footer: From the delivery report of 16 October
button: [Discuss in Claude Code](claude://code/new?prompt=Review%20the%20retry%20limit) filled blue
button: [Open the issue](https://github.com/uberblick-ai/uberblick-2/issues/1588)

Three of this week's wasted runs were third retries on the same failure. A limit of two would have stopped each one a run earlier.
:::

Header lines are label:, title:, footer: and button:, with title required; the first blank line ends the header and the rest is the body. A button is one Markdown link to an https:// address or to claude://code/new, claude-cli://open or codex://new, followed by an optional style (outline or filled) and colour (neutral, blue, green or violet). Adjacent cards stack full width; a blank line separates them in Markdown. An invalid card is refused over MCP with invalid_card and nothing is written; on import it stays plain paragraphs.

When to use one

For the one thing on a page a reader should act on: the recommendation at the end of a report, the next step after a review. A warning or a precondition is a callout, not a card. One card per page is the norm; a page full of cards is a list wearing boxes. Agents that write reports put the card last and link the issue or the record it rests on in the footer.

GitHub references

A link to an issue or pull request on GitHub renders as a compact pill with its number, and a decision record that links an issue is found by find_decisions for that issue. The pill does not fetch the issue; it is a reference, not a tracker.
