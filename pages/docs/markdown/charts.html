Charts

A document owns named collections of JSON records beside its prose. A chart or a data table is a few lines that say which collection and which fields. When an agent writes new records, every block that reads them refreshes, and nobody pastes a stale image again.

Source beside drawing

A chart pasted as an image is stale the day after. Here a document owns named collections of JSON records beside its prose, and a chart fence holds only the mapping: which collection, which fields. The values live in the records, so when an agent writes new ones, every chart and table that reads them refreshes, and the source stays a few lines of JSON that are easy to review.

```chart
{
  "version": 1,
  "type": "line",
  "title": "Pull requests per day",
  "collection": "pull_requests",
  "x": {"field": "day", "type": "date"},
  "y": [
    {"field": "opened", "label": "Opened"},
    {"field": "merged", "label": "Merged"}
  ]
}
```

In the editor, insert Line chart or Data table and edit the JSON source; over MCP an agent writes the same fence with the ordinary block tools. The mapping chooses a view, never the values: records sort by x, nothing is coerced, aggregated or derived, and a record that fails the collection's schema is left out and counted.

Where the numbers live

Every Uberblick document can hold custom JSON data next to its prose. The data is structured by a JSON schema that an agent defines and updates over MCP, and the records that fail it are kept, marked and left out of the drawings rather than breaking them. From the terminal, ub data prints and updates the same data, which is how a script or an Action feeds a report.

What it can show

The data draws as line charts, bar charts or data tables, with one chart per series as an option and a sortable table for the raw rows. We support a small set of visualizations on purpose; request what you need in a GitHub issue and we will add it. A chart draws up to 5,000 records. Charts render in the editor and export as their source fence; Markdown keeps the mapping but not the data, so an export alone cannot recreate a view.
