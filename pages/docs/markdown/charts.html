Charts

A document owns named collections of JSON records beside its prose. A chart or a data table is a few lines that say which collection and which fields. When an agent writes new records, every block that reads them refreshes, and nobody pastes a stale image again.

Source beside drawing

A chart pasted as an image is stale the day after. Here a document owns named collections of JSON records beside its prose, and a chart fence holds only the mapping: which collection, which fields. The values live in the records, so when an agent writes new ones with update_data, every chart and table that reads them refreshes, and the source stays a few lines of JSON that are easy to review.

```chart
{
  "version": 1,
  "type": "line",
  "title": "Pull requests per day",
  "collection": "pull_requests",
  "x": {"field": "day", "type": "date"},
  "y": [
    {"field": "opened", "label": "Opened"},
    {"field": "merged", "label": "Merged"}
  ]
}
```

In the editor, insert Line chart or Data table and edit the JSON source; over MCP an agent writes the same fence with the ordinary block tools. The mapping chooses a view, never the values: records sort by x, nothing is coerced, aggregated or derived, and a record that fails the collection's schema is left out and counted.

Where the numbers live

Each document has a data area: named collections, each with a JSON schema and records with an id and a value. Agents read it with get_data and write it with update_data, one validated batch per call: set the schema, replace or delete records, upsert whole records. Records that fail the schema are kept, marked invalid, and left out of every chart with a count of how many were skipped. get_doc reports the collection names and counts beside the blocks. From the terminal, ub data prints a collection as JSON and applies a batch from a file, which is how a script or an Action feeds a report.

Line, bar, table

  • Line: "type":"line", one x field of type number or date, and one to eight y series, each with a field and optional label, unit, axis range and reference line. "layout":"panels" draws one small chart per series with its latest value; "limit" keeps the latest N records; "missing" says whether a gap breaks or bridges the line.
  • Bar: the same mapping with "type":"bar" on a series. A bar-only chart is still "type":"line" at the top; bars draw behind lines when they share a chart, on their own axis.
  • Table: "type":"table" with one to thirty columns, each a field with an optional label and a text, number, date or link format, plus sort and limit. Readers sort the shown rows by clicking a header; that is never saved.

A chart never draws more than 5,000 records. Charts render in the editor and export as their source fence; Markdown keeps the mapping but not the data, so an export alone cannot recreate a view.
