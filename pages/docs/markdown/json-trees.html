JSON trees

People paste API responses, tool results and settings files into their pages. As code, three hundred lines of JSON are a wall of text. A json-tree fence shows the shape first and the details on demand, and the source stays the same JSON.

A JSON tree

Write the fence as json-tree instead of json. The editor draws a tree that opens as far as about twenty rows allow, and every object and array folds. Small snippets stay plain json and read as highlighted code. Any other Markdown tool sees an ordinary code block, and export_markdown gives back the text unchanged.

```json-tree
{
  "workflow": "release checks",
  "commit": "266d5061",
  "status": "failed",
  "checks": [
    {
      "name": "lint, typecheck and tests",
      "status": "passed",
      "seconds": 412
    },
    {
      "name": "browser chromium",
      "status": "failed",
      "seconds": 612,
      "failures": [
        {
          "spec": "revision-history.spec.ts",
          "line": 474,
          "error": "Test timeout of 60000ms exceeded."
        }
      ]
    },
    {
      "name": "macOS tests",
      "status": "passed",
      "seconds": 157
    }
  ],
  "limits": {
    "timeout": 3600,
    "retries": 1,
    "budget": 1.50
  }
}
```

Values as written

The tree reads the text itself instead of a parsed copy, so nothing is rounded or reordered on the way. 9007199254740993 stays that number, 1.50 keeps its zero, keys keep their order, and an object with a repeated key shows every occurrence. What the tree shows is what an agent reads over MCP.

Large ones

A long file opens full screen, with search across keys and values. Only the rows that are open are drawn, so a megabyte of JSON does not slow the page down. Folding is the reader's own and never changes the document.

In document history

When a JSON tree changed between two revisions, the comparison is by structure, not by line. Formatting and key order are no change. Array items are matched by id, key or name, so an item that moved shows as moved, and inside a changed value only the changed characters are marked. Before and after share one grid, so the two sides stay level however long a value is. Unchanged keys fold away, and the previous and next change buttons step through the changes inside the block.
