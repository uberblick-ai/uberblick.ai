Check the setup

Two commands tell you whether this computer is set up right, and what to fix when it is not.

ub doctor looks at the project you run it in and names the fix for each problem. It checks the workspace binding, the login, the local database, the hub, the clock against the hub, the local hub and web server, and whether an MCP client is registered for this project. Checks that do not apply are skipped and say why.

Terminal
$ ub doctor
uberblick 0.4.8

ok    workspace   Acme product (3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f), from ~/Projects/acme/.uberblick.json
ok    login       octocat on https://hub.example.com
ok    database    ~/.local/share/uberblick/3f0c2a1e-7b4d-4c2a-9e1f-5a6b7c8d9e0f.sqlite
ok    hub         connected to https://hub.example.com; octocat has access
ok    clock       within 2s of the hub
skip  local hub   no local hub is used; this workspace syncs through https://hub.example.com
skip  web server  127.0.0.1:13379 is not running; ub open starts it
warn  mcp         MCP client is not set up for this project
      → ub mcp install claude   (or codex)

0 failed, 1 warning, 5 passed, 2 skipped

A missing MCP client is a warning, not a failure: Uberblick works without agents. ub status is the short version: workspace, where the selection came from, local storage, the client and hub versions and the last sync. Both take --json for scripts; the full checks are on ub doctor.
