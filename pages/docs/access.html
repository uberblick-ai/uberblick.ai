Uberblick / Docs / Sharing

Access and membership

A local workspace has no access control; it is a file on your computer. A shared workspace on a hub admits members, and members are GitHub accounts. There are no Uberblick accounts to create.

Three roles

  • Member reads and writes every document in the workspace, from the browser and over MCP.
  • Workspace admin also manages members and roles and the workspace settings. The last admin cannot be demoted.
  • Hub admin runs the hub: sees every workspace on it, suspends and restores workspaces, and is the only one who can promote a new workspace onto the hub. The first GitHub account that signs in on a fresh hub claims it; the host operator appoints more with ub-hub hub-admin add.

Reading and writing are not separate rights. A workspace is a shared draft, and a reader who cannot comment is a reader on the wrong tool.

Signing in

Terminal
$ ub auth login https://hub.example.com
Open https://github.com/login/device and enter the code ABCD-1234
… signed in as ben; this computer holds a device credential for hub.example.com

Sign-in uses GitHub's device flow: open the address, enter the code, done. The hub learns your GitHub login and nothing else. The computer gets its own credential, which expires after 30 days and renews itself while in use. Signing in grants no workspace access by itself; an admin grants that. In the browser, Sign in with GitHub on the hub's address does the same for a browser session.

Granting access

Terminal
$ ub workspace member add dana --role member
grant dana (account 8213…) member of Uberblick product on hub.example.com? [y/N] y
$ ub workspace member list
ben    1024…  admin
dana   8213…  member

A workspace admin adds a GitHub login, confirms the resolved account, and the person can run ub workspace use with the link. member role changes a role, member remove ends access on every device. The same lives in the browser under Workspace settings, where a role is saved as soon as it is picked.

Devices and signing out

ub auth logout revokes this computer on the hub and removes its login; --all-devices revokes every device of your account, this one last. ub status and ub open tell you about recent sign-ins from other devices, so a credential that walked off is noticed. A lost laptop is handled from any computer still signed in.

Agents and unattended hosts

An agent uses the login of the computer it runs on; nothing is copied into an MCP config. An Actions runner or a server that runs agents signs in once with ub auth login like any other computer and holds its own device credential, which can be revoked on its own. A project binding that would move a workspace to another hub is refused.
