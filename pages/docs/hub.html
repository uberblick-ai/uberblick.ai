Uberblick / Docs / Get started

Run a hub

A hub shares a workspace between computers and people. Every computer keeps its own copy and works offline; the hub passes changes on and admits only members. It is one Docker release.

Start one

Terminal
$ /bin/bash -c "$(curl -fsSL https://uberblick.ai/setup-hub.sh)"

The script checks that Docker and Docker Compose are installed and recent enough, downloads the newest hub release into ~/uberblick-remote, writes a private .env, starts the hub with plain Docker Compose and waits until it answers. The hub listens on http://localhost:8080 of this computer and nowhere else. Documents and the claim live in named Docker volumes, so docker compose down and up -d keep them; only --volumes deletes them. The host needs no ub and no Node. To see what the script does, or to do it by hand, read REMOTE.md.

Claim it

Open http://localhost:8080 and choose Sign in with GitHub, or run ub auth login http://localhost:8080. The first account to sign in becomes the hub's administrator. It reports the default workspace's id; keep it for the other computers.

Let other computers reach it

Terminal
$ HUB_HOST=hub.example.com /bin/bash -c "$(curl -fsSL https://uberblick.ai/setup-hub.sh)"

Run the same line with the host name other computers will use, with port 443 open. The hub serves TLS itself on that name; a Tailscale name such as machine.tailnet.ts.net is routed through the tailnet instead. Clients refuse an unencrypted hub on another computer, so there is no insecure mode to forget to turn off.

Connect a computer

Terminal
$ ub auth login https://hub.example.com
$ ub workspace use https://hub.example.com/<workspace-id>
$ ub open

Add people with ub workspace member add. To share a workspace you already have, run ub workspace promote https://hub.example.com in its project and commit the .uberblick.json it writes; teammates then only need ub auth login.

With Kamal

We use it with Kamal: the hub runs as an accessory next to the app.

If you replace the web image's Caddyfile with your own, keep admin 127.0.0.1:2019 in its global options and import /etc/caddy/uberblick-csp.caddy in the route that serves the app. REMOTE.md explains why.

Keep it running

Terminal
$ docker compose exec hub ub-hub status
$ docker compose exec hub ub-hub doctor
$ docker compose exec hub ub-hub backup
$ docker compose logs --tail=100 hub caddy

ub-hub status shows the release, the database state and whether the hub is claimed; doctor checks hub, database, storage, GitHub and clock and names the fix for each warning. backup prints the path of a backup to copy off the host; to restore, stop the hub and run docker compose run --rm hub ub-hub restore <path>. Everything runs in the containers and never starts, stops or updates them.

To update, run the setup line again: it backs up, moves to the newest release and keeps your .env. A release that changes the sync protocol needs the hub and every client updated in the same sitting; restart agents and ub open and reload browser tabs. Rollback and recovery are in REMOTE.md.
