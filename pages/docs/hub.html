Run a hub

A hub shares a workspace between computers and people. Every computer keeps its own copy and works offline; the hub passes changes on and admits only members. It is one Docker release.

Start one

Terminal
$ mkdir -p ~/uberblick-remote && cd ~/uberblick-remote
$ for f in compose.yml remote.env.example remote.https.yml remote.tailscale.yml; do
    curl -fL -o $f https://github.com/uberblick-ai/uberblick-2/releases/download/hub-v0.4.8/$f
  done
$ cp remote.env.example .env && chmod 600 .env
$ docker compose config --quiet && docker compose up -d
$ docker compose exec hub ub-hub status

Four files from one hub release, a private .env with HUB_VERSION set to that release, and plain Docker Compose. The hub listens on http://localhost:8080 of this computer and nowhere else. Documents and the claim live in named Docker volumes, so docker compose down and up -d keep them; only --volumes deletes them. It needs Docker Engine 28 or newer and Compose 2.24 or newer on Linux x86_64, or Docker Desktop on macOS. The host needs no ub and no Node.

Claim it

Open http://localhost:8080 and choose Sign in with GitHub, or run ub auth login http://localhost:8080. The first account to sign in becomes the hub's administrator. It reports the default workspace's id; keep it for the other computers.

Let other computers reach it

Set one route in .env, then docker compose up -d again. The hub serves TLS itself on the host name you give it; clients refuse an unencrypted hub on another computer, so there is no insecure mode to forget to turn off.

RouteIn .env
This computer onlyCOMPOSE_FILE=compose.yml, the default
A public host nameWEB_HOST=hub.example.com with port 443 open, and COMPOSE_FILE=compose.yml:remote.https.yml
Tailscale (Linux)WEB_HOST=machine.tailnet.ts.net, TAILSCALE_IP from tailscale ip -4, and COMPOSE_FILE=compose.yml:remote.https.yml:remote.tailscale.yml

Connect a computer

Terminal
$ ub auth login https://hub.example.com
$ ub workspace use https://hub.example.com/<workspace-id>
$ ub open

Add people with ub workspace member add. To share a workspace you already have, run ub workspace promote https://hub.example.com in its project and commit the .uberblick.json it writes; teammates then only need ub auth login.

With Kamal

We use it with Kamal: the hub runs as an accessory next to the app.

If you replace the web image's Caddyfile with your own, keep admin 127.0.0.1:2019 in its global options and import /etc/caddy/uberblick-csp.caddy in the route that serves the app. REMOTE.md explains why.

Keep it running

Terminal
$ docker compose exec hub ub-hub status
$ docker compose exec hub ub-hub doctor
$ docker compose exec hub ub-hub backup
$ docker compose logs --tail=100 hub caddy

ub-hub status shows the release, the database state and whether the hub is claimed; doctor checks hub, database, storage, GitHub and clock and names the fix for each warning. backup prints the path of a backup to copy off the host; to restore, stop the hub and run docker compose run --rm hub ub-hub restore <path>. Everything runs in the containers and never starts, stops or updates them.

To update, back up first, fetch the newer release's four files the same way, keep .env and set HUB_VERSION, then docker compose config --quiet && docker compose pull && docker compose up -d. A release that changes the sync protocol needs the hub and every client updated in the same sitting; restart agents and ub open and reload browser tabs. Rollback and recovery are in REMOTE.md.
