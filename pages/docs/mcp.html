MCP reference

One server, ub mcp serve, registered by ub mcp install. Every tool below carries its full contract in its own description, so an agent needs none of this page; it is here for the person who wants to know what the agent can do. Reads are never gated; writes need the guidance reads first.

Find and read

  • get_sidebarThe curated navigation: named groups of pinned documents, in order. Where an agent starts.
  • list_docsEvery live document with title, tags, description, updated time and open thread count; decisions only with kind: decision.
  • searchDocuments containing the query words in title, description, content or tag names; word forms and prefixes match.
  • get_docA document's metadata, blocks with ids and revisions, threads, related decisions and code check.
  • backlinksThe documents that reference this one, by id.
  • find_decisionsLive decision records whose prose links a given GitHub issue or pull request.
  • list_tagsThe tag catalogue with stable ids and current names.
  • get_dataA document's data area or one collection, with schema, records and what is invalid.
  • export_markdownThe document as one Markdown file; blocks keep their source fences.
  • get_helpProduct help by topic or tool name, version-matched to the server.
  • sync_statusLocal replica state, pending rooms and the hub connection, with the reason for any refusal.

Write

  • create_docA new document or decision record, with a required description and optional first blocks.
  • insert_blockOne or more blocks after a block id, or at the top; returns their ids and revisions.
  • edit_blockReplace a block's text against the text and revision the agent read; a stale read returns the current text.
  • move_blockReorder blocks, keeping ids, revisions and comment anchors.
  • delete_blockDelete one block; refused while a comment thread is open on it.
  • link_rangeMark a span of prose as a reference to another document without changing its text.
  • update_dataOne validated batch on a document's collections: schema, replace, delete, upsert.
  • set_metadataTitle, description, TL;DR, tags, links, code check or decision discussion.
  • set_statusA document's lifecycle stage; a decision cannot be decided by an agent.
  • annotateOpen a comment thread on a range, reply, move an anchor, resolve or reopen.

Organise

  • pin_docPin a document into a sidebar group at a position; one pin per document.
  • unpin_docRemove it from the sidebar; the document is untouched.
  • sidebar_groupCreate, rename or delete a group.
  • archive_docArchive a document or a whole decision topic; reads by id still work.
  • restore_docUndo one layer of archiving.
  • delete_docPermanently delete an archived document on every replica. Cannot be undone.

Help topics

get_help without a topic lists them; each is also a resource at uberblick://help/<topic>. The topics are orientation, edit_doc, workspaces, decisions, markdown, ablauf, data, tools and tool-contracts. They are the same text for every workspace and match the server's version, so an agent never works from an outdated syntax page.

One failure shape

Every refusal is a tool error with a code, a sentence, and the fields needed to act: stale_block and old_text_mismatch return the current text and revision so the edit can be re-diffed without another read; open_thread_anchored names the thread; persistence_failed names the room. A failure of a writing tool also says what became of the write. The server never half-applies a batch.
